# pve-hw-metrics

Виджет «Hardware Metrics» на странице **Сводка** узла Proxmox VE: температура CPU, диски (SMART) и состояние UPS (NUT). Плюс консольная утилита `hw-metrics.sh` и простая веб-страница, которая показывает сразу несколько узлов.

Делал для себя, чтобы изредка заглянуть и увидеть, если что-то стало неладно. Проверено на PVE 9.2.26.

Лицензия: никакой, делай что хочешь.

## Установка

На каждом узле, от root:

```
./install-pve-metrics.sh
```

Спросит: адрес NUT, имя UPS (`auto` — найдёт сам), нужен ли веб, порт (9098), удалённые хосты. Потом Ctrl+F5 в браузере.

Нужны: `jq`, `python3`, `perl`, `smartctl`, `sensors` (lm-sensors), `upsc` (nut-client).

## Как это устроено

- Таймер `pve-metrics.timer` раз в 5 минут запускает `collect-hw-metrics.sh`, он пишет всё в `/var/cache/pve-metrics.json` (CPU, диски, UPS).
- Патч в `Nodes.pm` отдаёт этот файл в API узла как `custom_metrics`.
- Патч в `pvemanagerlib.js` рисует виджет на странице Сводка.
- `hw-metrics.sh` читает тот же кэш и печатает таблицы в консоль.
- `hw-metrics-web.py` (порт 9098) собирает вывод `hw-metrics.sh` с этого и удалённых узлов по ssh. Без авторизации, слушает все интерфейсы, рассчитано на домашнюю сеть. Нужен вход по ключу `root@хост`. На удалённых хостах сам ставит коллектор, если его нет.
- Конфиг: `/etc/pve-metrics.conf`.

## Что подсвечивается красным/оранжевым

- Диск со статусом не «ОК» (`FAIL`, `BAD!`, `WARN`, `CABLE`, `HOT!`). Пороги `HOT!` в `collect-hw-metrics.sh`: HDD/SSD выше 45 °C, NVMe выше 70 °C.
- CPU: от 85 °C оранжевый, от 95 °C красный (для AN3P: штатный максимум под нагрузкой около 80–90) (в блоке JS в установщике).
- UPS, если статус не `OL` (например, работает от батареи).

## После обновления Proxmox

Если обновился `pve-manager`, патчи пропадают (файлы заменяются). Просто запустить `install-pve-metrics.sh` ещё раз, он безопасно заменит блоки. Если виджет пропал, а скрипт ругается, что не нашёл якорь, значит в новой версии PVE поменялся код и патч надо подправить.

Патчи обёрнуты в маркеры `BEGIN/END pve_custom_metrics`, перед каждым запуском делаются бэкапы в `/var/lib/pve-dashboard-backup/` (`<файл>.<дата>.bak`, 5 последних). Если патч не прошёл проверку, файлы автоматически возвращаются как были.

## Откат

```
/usr/local/bin/uninstall-pve-metrics.sh
```

Создаётся установщиком. Вырезает наши блоки по маркерам (от бэкапов не зависит), удаляет сервисы, скрипты и конфиг; про удалённые хосты спросит отдельно.

Аварийно: `apt-get install --reinstall pve-manager proxmox-widget-toolkit`.

## Охлаждение и мощность (Chatreey AN3P, Ryzen 7 255)

Выбранная схема: `cpu-eco.sh 4 4000 --persist`, то есть governor `powersave`, EPP `balance_performance`, boost включён, потолок частоты 4000 МГц. Скрипт лежит в `/usr/local/sbin/cpu-eco.sh` (юнит `cpu-eco.service` ссылается на этот путь). Вернуть как было: `cpu-eco.sh 0 --persist`.

Замеры `stress-ng --cpu 0 --timeout 90` (16 потоков), максимум CPU / вентилятор:

| режим | частота | CPU | вентилятор |
|---|---|---|---|
| без ограничений (boost, governor performance) | ~4,4 ГГц | 95 °C (потолок) | 2975 RPM |
| 4, потолок 4200 | 4,17 ГГц | 85 °C | ~2590 RPM |
| **4, потолок 4000 (выбрано)** | 3,97 ГГц | 78 °C | ~2180 RPM |
| 3, boost выключен | 3,77 ГГц | 74 °C | ~1760 RPM |

Почему не BIOS: лимиты PPT (`Advanced → AMD CBS → SMU Common Options → SmartShift Control = Manual`) меняются только физически, с простоем трёх LXC/VM, а проверить, что BIOS их применил, заранее нельзя. Выигрыш от BIOS (полный разгон на лёгких нагрузках) невелик. ryzenadj не используется (внешний модуль, поддержка этого чипа не проверена).

Особенности железа: штатная кривая вентилятора (EC) реагирует с запаздыванием около 10 секунд, поэтому температура успевает подскочить раньше. Вентилятор отдаёт сторонний драйвер `it5570_fan` (DKMS, ставится `install-it5570-fan.sh`). Верим: обороты, pwm, «CPU Die», Board, Chipset. Не верим: «EC» (всегда 1 °C), Heatsink без эталона. Запись `pwm1` работает (`pwm1_enable`: 1 ручной, 2 авто), но кривую не трогаем: в ручном режиме EC перестаёт сам поднимать обороты.

## Вспомогательные файлы

- `cpu-eco.sh`: профили питания CPU (0..4), см. выше.
- `install-it5570-fan.sh`: установка DKMS-драйвера вентилятора.
- `tools/thermal-watch.sh [секунд] [интервал]`: замер температуры, частоты и оборотов с итогом; для сравнения «до/после» любых изменений (`stress-ng --cpu 0 --timeout 90 & ./thermal-watch.sh 90 2`).
- `tools/it5570-check.sh [секунд]`: диагностика драйвера (какие каналы живые и сходятся ли с Tctl), только чтение; пригодится на новой машине или после обновления драйвера.
- `hw-metrics-web.ico`: иконка для Flame.

## Сеть: `.local` и mDNS

После `apt install chromium` подтянулись `avahi-daemon` и `libnss-mdns`, и `ssh/scp` перестали резолвить `*.local` (nslookup при этом работает: он спрашивает DNS напрямую, а ssh идёт через `/etc/nsswitch.conf`). Исправлено в `hosts: files dns mdns4_minimal` (обычный DNS первым). Если на другом хосте вдруг «Name or service not known» для `.local`, смотреть эту строку.

## Что полезно помнить

- Попутно отключается nag-экран про подписку (`proxmoxlib.js`). Это необязательная часть: если не сработает, скрипт только предупредит и пойдёт дальше.
- `printf` в bash считает ширину колонок в **байтах**, а кириллица занимает по 2 байта на букву. Поэтому заголовки таблиц в `hw-metrics.sh` дополнены пробелами вручную. Не «исправлять».
- Файл метрик читается в Perl через `utf8::decode`, иначе кириллица (статус «ОК») приходит в браузер сломанной.
- Пустые поля в таблицах разделены символом `0x1f`, а не табом, иначе пустое значение «съедает» колонку.
- Use% диска считает коллектор. Обычные разделы: как df. Если на диске LVM (NVMe с Proxmox по умолчанию): данные в смонтированных ФС плюс реально занятое место thin-пулов (`local-lvm`), делённые на размер диска. ФС на thin-томах не считаются дважды.
- Менял коллектор: поднять `COLLECTOR_VERSION` (в самом коллекторе и в проверке в `hw-metrics-web.py`), иначе удалённые хосты не обновятся. Ставить сначала на хост с веб-сервисом.
- Датчики берутся из `sensors` одним вызовом: CPU (Tctl/Package id 0), вентиляторы (RPM, нулевые разъёмы не в счёт), температура RAM (spd5118/jc42, если модули отдают), температура сетевой карты (r8169 и др.). Сознательно НЕ берутся: Heatsink/EC у it5570_fan (Heatsink показывал 88 °C при CPU 40 °C, EC 1 °C, похоже на мусор), acpitz (константа 20 °C), amdgpu edge (повторяет CPU).
- Пороги в блоке JS установщика: CPU 85/95, RAM 70/85, NIC 85/100, вентилятор 0 RPM красный при CPU от 60 °C.
- Диски опросом не усыпляю: HDD в DAS намеренно держу бодрыми, `smartctl -n standby` не используется.
