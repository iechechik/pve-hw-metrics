# pve-hw-metrics

Виджет «Hardware Metrics» на странице **Сводка** узла Proxmox VE: температура CPU, диски (SMART) и состояние UPS (NUT). Плюс консольная утилита `hw-metrics.sh` и простая веб-страница, которая показывает сразу несколько узлов.

Делал для себя, чтобы изредка заглянуть и увидеть, если что-то стало неладно. Проверено на PVE 9.2.26.

Лицензия: никакой, делай что хочешь.

## Установка

На каждом узле, от root:

```
./install-pve-metrics.sh
```

Спросит: адрес NUT, имя UPS (`auto` — найдёт сам), нужен ли веб, порт (9098), удалённые хосты. Потом Ctrl+F5 в браузере.

Нужны: `jq`, `python3`, `perl`, `smartctl`, `sensors` (lm-sensors), `upsc` (nut-client).

## Как это устроено

- Таймер `pve-metrics.timer` раз в 5 минут запускает `collect-hw-metrics.sh`, он пишет всё в `/var/cache/pve-metrics.json` (CPU, диски, UPS).
- Патч в `Nodes.pm` отдаёт этот файл в API узла как `custom_metrics`.
- Патч в `pvemanagerlib.js` рисует виджет на странице Сводка.
- `hw-metrics.sh` читает тот же кэш и печатает таблицы в консоль.
- `hw-metrics-web.py` (порт 9098) собирает вывод `hw-metrics.sh` с этого и удалённых узлов по ssh. Без авторизации, слушает все интерфейсы, рассчитано на домашнюю сеть. Нужен вход по ключу `root@хост`. На удалённых хостах сам ставит коллектор, если его нет.
- Конфиг: `/etc/pve-metrics.conf`.

## Что подсвечивается красным/оранжевым

- Диск со статусом не «ОК» (`FAIL`, `BAD!`, `WARN`, `CABLE`, `HOT!`). Пороги `HOT!` в `collect-hw-metrics.sh`: HDD/SSD выше 45 °C, NVMe выше 70 °C.
- CPU: от 80 °C оранжевый, от 90 °C красный (в блоке JS в установщике).
- UPS, если статус не `OL` (например, работает от батареи).

## После обновления Proxmox

Если обновился `pve-manager`, патчи пропадают (файлы заменяются). Просто запустить `install-pve-metrics.sh` ещё раз, он безопасно заменит блоки. Если виджет пропал, а скрипт ругается, что не нашёл якорь, значит в новой версии PVE поменялся код и патч надо подправить.

Патчи обёрнуты в маркеры `BEGIN/END pve_custom_metrics`, перед каждым запуском делаются бэкапы в `/var/lib/pve-dashboard-backup/` (`<файл>.<дата>.bak`, 5 последних). Если патч не прошёл проверку, файлы автоматически возвращаются как были.

## Откат

```
/usr/local/bin/uninstall-pve-metrics.sh
```

Создаётся установщиком. Вырезает наши блоки по маркерам (от бэкапов не зависит), удаляет сервисы, скрипты и конфиг; про удалённые хосты спросит отдельно.

Аварийно: `apt-get install --reinstall pve-manager proxmox-widget-toolkit`.

## Что полезно помнить

- Попутно отключается nag-экран про подписку (`proxmoxlib.js`). Это необязательная часть: если не сработает, скрипт только предупредит и пойдёт дальше.
- `printf` в bash считает ширину колонок в **байтах**, а кириллица занимает по 2 байта на букву. Поэтому заголовки таблиц в `hw-metrics.sh` дополнены пробелами вручную. Не «исправлять».
- Файл метрик читается в Perl через `utf8::decode`, иначе кириллица (статус «ОК») приходит в браузер сломанной.
- Пустые поля в таблицах разделены символом `0x1f`, а не табом, иначе пустое значение «съедает» колонку.
- Диски опросом не усыпляю: HDD в DAS намеренно держу бодрыми, `smartctl -n standby` не используется.
